# Система DNS

Чтобы загрузить сайт, браузер должен знать IP-адрес сервера, на котором размещён этот сайт. Но запоминать IP-адреса множества сайтов неудобно, поэтому серверам дают доменные имена — например, `example.com` вместо `93.184.216.34`.

Система DNS (Domain Name System) — это распределённая база данных, к которой браузер обращается при открытии сайта. Она позволяет автоматически сопоставлять доменные имена с IP-адресами. 

## Алгоритм работы системы DNS

Когда вы вводите доменное имя в браузере:

1. Браузер проверяет свой кэш — если в нём нет нужной записи, запрос передаётся операционной системе устройства, с которой вы отправляете запрос.
2. Операционная система проверяет свой кэш — если в нём нет нужной записи, запрос передаётся рекурсивному серверу.

    ::: info

    Как правило, рекурсивным сервером выступает DNS-сервер вашего провайдера или публичный сервис — например, Google Public DNS (8.8.8.8) или Cloudflare DNS (1.1.1.1).

    :::

3. Рекурсивный сервер проверяет свой кэш — если в нём нет нужной записи, он последовательно опрашивает серверы иерархии DNS: корневой сервер, затем TLD-сервер, затем авторитативный сервер домена. Подробнее о [видах DNS-серверов](#dns-server-types).
4. Полученный IP-адрес возвращается браузеру и кэшируется  на нескольких уровнях — в браузере, в операционной системе и на рекурсивном сервере. Следующее открытие сайта будет быстрее.

## Виды DNS-серверов {#dns-server-types}

Система DNS работает благодаря DNS-серверам — устройствам, которые обмениваются запросами по общему протоколу, чтобы находить IP-адреса доменов. DNS-серверы подчиняются строгой иерархии. 

| Вид DNS-сервера    | За что отвечает |
|-------------------|------------------|
| Рекурсивный сервер | Принимает запрос от браузера и выполняет поиск IP-адреса. Опрашивает другие DNS-серверы по цепочке |
| Корневой сервер    | Принимает запрос от рекурсивного сервера и сообщает IP-адрес сервера, который отвечает за нужный <Tooltip text="Последняя часть интернет-адреса после точки, например .com, .ru, .net, .org">домен верхнего уровня</Tooltip> |
| Сервер домена верхнего уровня (TLD-сервер) | Принимает запрос от рекурсивного сервера и сообщает IP-адрес сервера, который относится к конкретному домену верхнего уровня и хранит базу записей домена | 
| Авторитативный сервер | Принимает запрос от рекурсивного сервера и возвращает IP-адрес нужного домена |

## Частые вопросы

### Чем публичный DNS-сервер отличается от DNS-сервера провайдера?

Провайдер предоставляет DNS как часть услуги доступа в интернет. Он может фильтровать или логировать ваши запросы, например, блокировать определённые домены в соответствии с требованиями законодательства.

Публичный DNS — это независимый сторонний сервис, который обычно делает акцент на безопасности и скорости. Кроме того, публичный DNS обычно поддерживает более новые протоколы шифрования (например, DNS over HTTPS), что снижает риск перехвата запросов при передаче.

### Что такое DNS-утечка?

DNS-утечка — это ситуация, когда ваши DNS-запросы не проходят через предназначенный для них защищённый канал (например, VPN-туннель), а отправляются напрямую вашему интернет-провайдеру или другому незапланированному DNS-серверу.
